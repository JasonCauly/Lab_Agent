## 已有数据库的升级

模型声明唯一约束只会影响新建表，`Base.metadata.create_all()` 不会为已有表补上约束。
已有数据库需要在停止注册和管理员创建账号等写入后，在 `backend` 目录执行：

```powershell
.\.venv\Scripts\python.exe -m app.migrations.add_username_unique
```

脚本读取项目数据库配置，为已有 `users.username` 添加 `uq_users_username` 唯一索引。
重复执行会跳过已有的用户名唯一约束。
如果已有重复账号，脚本会停止，不修改账号或预约数据；需先人工核实身份及历史预约归属，再处理重复账号并重新执行。

可用以下查询排查重复账号：

```sql
SELECT username, COUNT(*) AS account_count
FROM users
GROUP BY username
HAVING COUNT(*) > 1;
```

本次开发和测试未连接现有 MySQL，未对其执行升级或修改业务数据。

## 事务与并发说明

MySQL 部署要求相关表使用 InnoDB。
预约通过不改变字段值的 `UPDATE labs` 持有行锁，显式保留实验室更新时间；同一实验室的提交在事务内依次校验和写入。
冲突查询使用锁定读，以读取最新已提交预约，避免认证查询先建立的 REPEATABLE READ 快照漏掉刚提交的记录。

MySQL 死锁会回滚并重试整个预约事务，最多执行三次；锁等待超时或重试耗尽时返回业务码 409，提示稍后重试。
其他数据库异常仍按原有异常处理路径上报。
锁定读和死锁处理依据 [MySQL 锁定读文档](https://dev.mysql.com/doc/refman/8.4/en/innodb-locking-reads.html)及 [InnoDB 死锁处理文档](https://dev.mysql.com/doc/refman/8.4/en/innodb-deadlocks-handling.html)。
